# 服务端执行与存储加密

本项目采用受信任的服务端执行架构。浏览器负责交互，后端连接 SSH、调用 AI 模型、执行工具、管理任务和保存结果。桌面继续使用本机执行能力，并可授权同步到同一 Web 账户。

## 执行与安全边界

- SSH、SFTP、Docker、监控、脚本、AI 代理及后台任务恢复服务端执行链路。
- 浏览器通过受认证的 HTTP、WebSocket 和流式接口交互。后台任务和 AI 运行不依赖浏览器持续打开；交互式终端连接仍遵守原来的生命周期。
- SSH 密码、私钥、AI API Key 与同步秘密沿用服务端／桌面的存储加密和现有实例密钥管理。运行中的后端能够解密使用，不属于端到端加密。
- TLS 保护网络传输。数据库本身并非全库加密，任务输出、AI 历史、日志等仍遵循原有存储模型。
- 运行时入侵仍可能使用后端的解密能力。完整实例备份包含恢复所需的根密钥，但整个归档由单独的备份密码保护；裸数据库导出不等于完整备份。
- 权限、AI 操作确认、取消和审计恢复原有实现，本轮不追加新的策略或强化承诺。

## 账户与界面

- 使用普通账户密码登录，密码以 bcrypt 哈希存储；至少 9 个 Unicode 字符、最多 72 字节。
- 保留登录会话、闲置退出、记住登录、两步验证、Google 绑定与登录二次验证。
- 自助注册由管理员控制，邮箱验证可独立开启；未验证邮箱不允许自动关联同邮箱 Google 账号。
- 初始化、注册及账户设置保留简洁布局，移除业务解锁、主密码恢复码、加密设备授权链及浏览器密钥保留包。
- 忘记密码恢复邮件验证流程，SMTP 不可用时需要管理员协助。
- 账户设置集中管理登录会话，数据与同步页管理桌面同步授权；用户管理在系统设置复用同一页面。

## 同步

- 服务器配置、脚本通过同一账户同步；凭据、个人 AI 配置及 AI 历史按原有独立范围授权与启用。
- 服务器自定义排序使用配置同步协议 4。顺序使用远端服务器 ID；桌面投影只调整当前同步空间的服务器位置，保留未加入同步的本地服务器。
- 服务端参与数据合并与秘密解密，凭据和同步秘密在落盘前加密。
- 撤销设备令牌阻止后续同步，不远程抹除设备已下载的数据。

## 开发与部署

- 浏览器 Worker／WASM 执行引擎、客户端加密协议与自动编译监听已移除。前端开发恢复 pnpm dev，构建恢复普通 Vite 流程。
- 服务端重新需要原有 Node 同步运行时；Docker、开发脚本与 Makefile 恢复对应打包和依赖流程。
- 数据库按开发环境新项目处理，仅保留版本 4 的全新初始化基线；不自动升级或转换旧库。现有数据库文件不会在本次源码修改中被删除。
- 重新部署时使用全新数据库与匹配版本的前后端、桌面程序。旧版端到端加密数据及备份不承诺导入当前版本。
- 本轮未执行构建、自动测试或实际登录／任务运行验收。
