# 实例备份、设备同步与新库初始化

日常跨端使用设备同步，整体恢复使用加密完整备份。完整备份采用 SQLite / PostgreSQL / MySQL 原生能力；Goose 负责数据库版本。通用 JSON 数据导出、预览和导入已移除，原有应用数据 JSON 文件不能在当前版本导入。代码不会自动删除或改造未纳入版本管理的历史数据库。

## 适用入口

| 目的 | 入口 | 内容 |
| --- | --- | --- |
| 故障恢复、升级前恢复点 | 系统设置 → 备份与恢复 → 完整备份；应急时使用 `maintenance backup` / `restore` | 原生数据库快照、数据目录、文件传输存储和根密钥 |
| Web 与桌面、多台桌面之间共享个人数据 | Web 账户设置 → 数据与同步；桌面顶部云图标旁的下拉菜单 → 同步设置 | 绑定远端账户，同步本人服务器配置、脚本，以及单独授权并开启的凭据、个人 AI 配置和 AI 历史 |
| 全新数据库 | 普通启动 | 按当前初始化基线创建空库；不升级旧库 |

通过命令行执行完整备份前，必须先退出正常进程。系统内置入口复用原生快照与归档实现，无需手动停止服务。普通启动与维护共用操作系统文件锁，PostgreSQL/MySQL 还持有数据库会话级锁，避免另一台主机上的 EasySSH 同时写入同一个数据库。这也意味着同一数据库同时运行多个 EasySSH 进程不再受支持。外部 SQL 客户端不会遵守应用锁；维护期间不要用其他工具修改该数据库或文件目录。

命令由已构建的程序提供，不依赖 HTTP 服务是否能够启动。

## 系统内置操作与历史

Web 和桌面端均提供创建、上传、下载、校验、恢复副本、删除、搜索和分页。创建、校验、恢复在后台执行，页面每 3 秒更新状态。备份密码仅存于当前任务内存，不写入历史或日志；每次校验和恢复重新输入密码。

历史记录使用备份目录中的独立 JSON 元数据，包含文件名、时间、大小、来源、状态、错误、版本、校验时间和恢复目录，不占用业务数据库。重启后中断任务标为失败或保留可用文件并显示中断原因。删除操作同时删除归档和历史，保留当前业务数据和已经恢复的副本；正在下载的归档不能删除。

- 服务端默认目录是数据目录旁的 `backups`，可通过 `EASYSSH_BACKUP_DIR` 指定。目录必须与业务数据目录和传输存储互不包含。
- 桌面端默认目录同样为数据目录旁的 `backups`，可通过 `EASYSSH_DESKTOP_BACKUP_DIR` 指定；上传和下载调用系统文件对话框。
- Docker 镜像使用 `/app/backups`；Compose 已增加独立持久化挂载（生产 `./backups`，开发 `./backups-dev`）。应用用户必须对挂载目录有写权限。
- 上传上限为 16 GiB，解压上限为 256 GiB；上传完成仅表示文件已保存，仍需密码校验。临时目录需要容纳解压数据。
- Web 下载使用限定到单个归档的一次性短期票据，由浏览器直接保存，不在页面内存缓存完整文件；下载端点仍检查 `backup:manage` 权限。

服务端备份期间阻止传输文件写入、删除和清理，以及传输存储配置变更；若已有传输或清理正在执行，本次任务显示原因，待任务结束后重新创建。数据库由原生快照提供事务一致性，其他不修改本地附件的服务可继续运行。桌面端收集快照时协调配置、通知、主机指纹文件和日志写入。外部工具修改文件或数据库不受应用锁控制。

**“校验”验证归档校验和、应用形态、数据库类型与版本要求；“恢复副本”才会实际恢复数据库并校验凭据。两者都不表示已切换当前实例。** 恢复副本写入 `backups/restored/<id>-<time>`，页面显示其目录；SQLite 可直接生成副本，PostgreSQL/MySQL 需预先配置 `EASYSSH_RESTORE_DSN` 指向新的空库。使用启动器的服务端磁盘 SQLite（本地运行、Docker）和桌面端可在恢复后单独确认“启用并重启”；外部数据库仍使用下文的手动配置切换流程。

### 服务端磁盘 SQLite：启用并重启

部署包含此功能的新前后端版本后，按原方式启动服务端程序一次即可。磁盘 SQLite 的正常入口自动作为启动器运行，再启动实际 HTTP 服务子进程；现有账号、数据库格式、备份文件和 API 不变。无需额外安装启动器，也不编辑 `.env`。外部数据库、SQLite URI 和内存数据库不启用此流程；需要完全绕过启动器时设置 `EASYSSH_INSTANCE_LAUNCHER=off`。

1. 在完整备份页面恢复副本，等待成功。
2. 点击该行“启用并重启”，核对备份名称和时间，确认连接中断及重新登录提示。
3. 启动器持久化切换意图，通知旧服务优雅退出，等待其数据库与目录锁释放。正在进行的备份、恢复及归档下载会阻止启用。
4. 启动所选目录，统一使用对应数据库、根密钥和原备份目录。完成数据库连接、凭据解密、服务初始化及 HTTP 端口绑定后才提交选择；任务队列在选择提交前不执行任务，通知工作线程也不会提前发送通知。
5. 页面进入无需旧登录会话的等待页，仅用随机操作标识查询结果。服务可访问并返回成功状态后，点击“重新登录”，使用备份中的账号核对数据。

新实例未通过上述启动校验时自动回到切换前实例。旧服务 60 秒内不能退出时终止其进程树并重新启动原实例，不继续启用副本；新服务启动校验最长等待 90 秒。程序或机器在切换意图提交后、选择确认前中断时，下次启动回到切换前实例。确认启用后的日常运行故障不触发自动来回切换。页面五分钟仍未取得结果时显示“未确认”，不会把单纯端口可达当成成功。

页面提供“切回上一实例”：保留两份数据目录，只切换启动选择，不把切换后的新数据合并回去。启用后原备份历史仍可见；备份存储检查仅对启动器选中的 `backups/restored/` 子目录放行，其他目录重叠仍被拒绝。不要移动已启用目录，其中传输文件引用仍使用恢复时的绝对路径。

启动器使用工作目录下的 `.easyssh-runtime/selection.json` 保存当前、上一实例和未完成的切换意图，通过写入临时文件再原子替换持久化。该目录还保存原实例的根密钥，Windows ACL 限制为运行账号、SYSTEM 和管理员，Unix 目录权限为 0700、文件为 0600；不要删除或提交到 Git。可通过 `EASYSSH_INSTANCE_STATE_DIR` 指定固定绝对路径，必须与数据库目录、备份目录分开。应固定启动工作目录和运行账号；更换可执行文件无需重置选择。已保存的实例选择优先于原 `.env` 的数据库与密钥配置；端口等其他部署配置继续从原环境读取。

应急手动切回：先停止启动器，再设置 `EASYSSH_INSTANCE_LAUNCHER=off`，使用原 `DB_DSN` 和原根密钥启动。原 `.env` 未被修改；若原来未显式配置密钥，原数据目录的 `easyssh-root.key` 仍保留。保留 `.easyssh-runtime` 可继续检查切换记录，排障前不要删除任一实例。完整备份恢复到其他机器仍按归档恢复流程执行，不需要复制本机启动器状态。

### Docker

Docker 镜像的启动入口使用 tini 回收进程；EasySSH 启动器接收停止信号并等待服务子进程退出。标准输出和错误输出均转发至容器日志。生产与开发 Compose 均增加独立命名卷保存 `/app/instance-state`，原数据和备份目录挂载保持不变。`stop_grace_period: 75s` 为优雅退出保留时间。

升级已有部署时需要同时更新镜像及 Compose 配置；首次启用副本前确认数据、备份、启动器状态三处都持久化，且容器账号能写入。不使用 Compose 时需自行给 `/app/instance-state` 挂载持久卷，并设置至少 75 秒的停止超时。不要删除状态卷或执行清除该卷的命令，否则重建后可能重新选择原环境中的数据库。根密钥与状态卷一同按敏感数据保护。容器健康检查在切换间隙可能暂时失败，外部探活管理器应给切换留出时间，避免打断回退。

### 桌面端：启用恢复副本

桌面端使用同一切换与回退状态机；点击“启用并重启”后窗口退出并重新打开，不进入 Web 登录等待页。候选数据库、凭据解密和所有 Wails 服务通过初始化、主窗口运行时就绪后才提交选择；前端启动入口等待提交完成，再挂载业务页面，任务历史清理也在提交后执行。不能仅凭应用事件循环启动就确认成功，因为此时 WebView2 可能仍在初始化。新窗口会提示成功或回退，备份页也保留最后结果和“切回上一实例”。正在进行的终端、传输和 AI 请求会中断。

默认启动器状态为原数据目录旁的 `.easyssh-desktop-runtime`，可以用 `EASYSSH_INSTANCE_STATE_DIR` 指定；该目录的 `launcher.log` 保存父进程启动与回退信息。桌面密钥始终保存在系统凭据库，不写入启动器文件或子进程环境。旧数据目录继续使用原凭据条目；每个新恢复副本使用独立凭据条目，目录内 `.easyssh-key-account` 仅保存条目标识。失败或回退不会覆盖原密钥；不要手工删除仍被副本引用的凭据条目。跨机器恢复应上传加密归档重新恢复，不能只复制数据目录及条目标识。

自动更新的独立帮助进程会等待桌面子进程和启动器均退出后再替换程序，重新启动时沿用持久化选择。手工应急启动可设 `EASYSSH_INSTANCE_LAUNCHER=off` 和 `EASYSSH_DESKTOP_DATA_DIR` 指向原目录；也可按下文维护命令恢复到新目录。禁用启动器后不显示一键启用入口。

命令行仍作为无法登录或系统无法启动时的应急入口，不依赖历史列表。旧的手工命令行归档不会自动出现在列表，可通过“上传已有备份”纳入管理。

## 服务端完整备份

1. 停止 EasySSH 服务，保留原有 `DB_DRIVER`、`DB_DSN`、`ENCRYPTION_KEY` 和数据目录配置。
2. 准备只允许操作者读取的密码文件，例如 `/secure/backup-password`。密码不放在命令参数中。
3. 将备份写入数据目录之外：

```sh
./easyssh-api maintenance backup \
  --file /backups/instance.easyssh.age \
  --password-file /secure/backup-password
```

命令检查数据库版本、凭据解密和 SQLite 完整性，创建原生快照，收集数据目录及配置的传输存储，然后流式生成 age 加密的 tar.gz 归档。源文件不允许是符号链接或特殊文件，避免生成缺失外部内容的备份。归档清单记录应用版本、数据库类型和版本、迁移版本、文件长度和 SHA-256。输出文件必须不存在。

SQLite 使用 `VACUUM INTO`，包含已提交的 WAL 内容。不会直接复制运行中的主数据库文件。PostgreSQL 使用 `pg_dump --format=custom`；MySQL 使用 `mysqldump --single-transaction`，要求业务表为 InnoDB。镜像包含 PostgreSQL 和 MariaDB 原生客户端；独立二进制部署需自行安装与数据库版本匹配的客户端。PostgreSQL 的 dump 客户端不能低于源服务端主版本。

MySQL 原生连接支持 unix socket、TCP 和驱动的 `tls=true/false/skip-verify/preferred` 设置；应用自定义注册的 TLS 配置不能自动转成原生客户端配置。MySQL 基线要求 MySQL 8.0.13+，使用表达式默认值；MariaDB 部署须按其版本验证相应 SQL 和客户端兼容性。

默认数据目录：SQLite 为数据库文件所在目录，PostgreSQL/MySQL 为 `EASYSSH_DATA_DIR`，未配置时为当前工作目录下的 `data`。备份根密钥使用应用实际加载的值，即使它来自 `ENCRYPTION_KEY` 环境变量也会加密保存。数据库连接口令不写进备份，恢复时由目标部署提供。反向代理、容器编排和外部服务配置仍由部署管理，不属于应用数据目录。

## 检查和恢复


```sh
./easyssh-api maintenance inspect \
  --file /backups/instance.easyssh.age \
  --password-file /secure/backup-password

./easyssh-api maintenance restore \
  --file /backups/instance.easyssh.age \
  --password-file /secure/backup-password \
  --into /srv/easyssh-restored
```

`inspect` 会解密、读取并核对所有文件。需要足够的临时磁盘空间；归档解压上限为 256 GiB。它验证归档完整性，不代替数据库恢复演练。

`restore` 要求 `--into` 不存在。流程如下：

1. 在权限受限的临时目录解密并核对清单，拒绝重复路径、路径穿越、符号链接和多余内容。
2. 检查应用版本，并要求归档的数据库基线与当前程序完全一致。
3. SQLite 恢复到临时数据库；PostgreSQL/MySQL 恢复到操作者提供的空数据库。
4. 不执行旧库转换；验证根密钥能够解密应用凭据，SQLite 另检查数据库与外键完整性。
5. 清理登录会话、设备授权和短期认证请求，防止旧快照复活已撤销授权；保留资源及同步文档。传输文件路径调整为恢复目录内的 `transfers`。
6. 把恢复完成的文件发布到新目录，输出该目录。**不会自动替换原实例或启动服务。**

SQLite 切换时，将 `DB_DSN` 设置为 `/srv/easyssh-restored/easyssh.db`。保留旧目录，即可在停止新实例后切回。根密钥从恢复目录的 `easyssh-root.key` 读取；必须取消旧的 `ENCRYPTION_KEY` 覆盖，或确保它与恢复密钥完全相同。

PostgreSQL/MySQL 恢复前，创建独立空数据库，并通过 `EASYSSH_RESTORE_DSN` 环境变量提供相应的 Go 驱动 DSN。可以用 `--target-dsn-env OTHER_VARIABLE` 指定其他环境变量名。恢复后将正常服务的 `DB_DSN` 指向该数据库，将 `EASYSSH_DATA_DIR` 指向恢复目录，并使用恢复根密钥。原数据库保持保留。

PostgreSQL 的原生导入使用单事务；MySQL DDL 无法保证整体事务回滚。若 MySQL 导入失败，目标是隔离的新数据库，原实例不受影响；删除失败的临时目标库并重新创建空库后再重试。程序不会擅自清空数据库。

完整备份只在同一数据库类型、同一应用形态内恢复。服务端与桌面端之间的个人数据通过设备同步流转。SQLite、PostgreSQL、MySQL 之间的数据库类型转换需要另行制定迁移方案，当前产品不提供通用迁移入口。

## Docker

先准备宿主机备份目录和密码文件，确保容器中的应用用户有适当权限。在 `docker` 目录使用项目的 Compose 配置：

```sh
docker compose stop easyssh
docker compose run --rm --no-deps \
  -v /srv/backups:/backups \
  -v /srv/secrets/backup-password:/run/secrets/backup-password:ro \
  easyssh ./easyssh-api maintenance backup \
  --file /backups/instance.easyssh.age \
  --password-file /run/secrets/backup-password
docker compose start easyssh
```

恢复时将新的宿主机父目录挂载进维护容器，把 `--into` 指向该挂载下尚不存在的子目录。确认成功后再修改正常服务的数据卷或数据库连接。Compose 管理的现有数据卷不要在恢复命令中直接覆盖。

## 桌面端

完整退出应用（仅关闭窗口可能仍在托盘运行），使用桌面程序同样的子命令：

```sh
EasySSHDesktop maintenance backup --file /backups/desktop.easyssh.age --password-file /secure/backup-password
EasySSHDesktop maintenance inspect --file /backups/desktop.easyssh.age --password-file /secure/backup-password
EasySSHDesktop maintenance restore --file /backups/desktop.easyssh.age --password-file /secure/backup-password --into /new/desktop-data
```

Windows 使用实际的 `.exe` 路径；macOS 使用应用包内的可执行文件路径。命令在 Wails 和界面启动之前执行。

默认数据目录仍为可执行文件旁的 `data`；可通过 `EASYSSH_DESKTOP_DATA_DIR` 指定恢复目录。完整备份加密保存系统凭据库中的根密钥。恢复时会检查数据库凭据、同步对象和代理密码；恢复成功时为副本创建独立系统凭据条目，并保存条目标识；原实例密钥保持不变。已有旧数据目录不需要迁移凭据条目。恢复后的设备同步需要重新授权。

## 设备同步与数据边界

桌面端设备同步入口位于顶部设置菜单前的云图标。云图标只负责立即同步，不打开页面；未配置、已暂停或状态加载失败时禁用，并提示通过下拉菜单进入同步设置。已绑定并启用时，点击立即同步，原有自动同步继续运行。只有云图标旁下拉菜单中的“同步设置”打开设置页面，用于修改同步范围、加入本地数据、处理冲突，或退出绑定后更换服务端和账户。同步中显示进度图标，失败或冲突显示提示点。备份与恢复页面只管理完整备份，Web 与桌面共用页面布局。

桌面端填写服务端地址，通过浏览器登录并授权远端账户。多台桌面绑定同一账户后，通过服务端交换数据；Web 页面直接使用该账户的服务端数据。首次连接接收远端基础配置，现有本地配置不会自动上传。桌面新建的服务器和脚本也需要主动加入当前同步空间。

- 基础范围：本人服务器连接参数、名称、分组、标签、描述、自定义排序，以及个人脚本。共享资源不纳入同步。
- 可选范围：已同步服务器的密码和 SSH 私钥、个人 AI 配置与 API Key、AI 会话与历史。每个范围都需要设备授权，并在桌面单独开启。系统共享 AI Key 不参与同步。
- AI 会话：已有本地会话需手动加入；开启会话同步后，新建会话自动加入当前空间。同步包含消息、附件和历史工具结果，接收端以只读权限和空闲状态保存，不恢复运行中的终端连接或执行历史任务。
- 本地 AI 配置：通过“将本地 AI 配置复制到当前空间”主动加入；绑定账户不会自动用本地配置覆盖远端配置。
- 排序：新设备的空列表不产生排序修改；只因已删除服务器 ID 不同、实际顺序一致的历史不提示冲突。实际顺序不同的并发修改仍需选择版本。
- 冲突与删除：连接参数、脚本内容及排序有冲突时保留本端当前生效值；首次接收且有冲突的记录暂不加入业务列表。只有明确选择版本才应用冲突字段，其他字段正常同步。AI 会话可另存版本；删除会传播到其他设备。同步不能替代备份。
- 状态与授权：查看 Web 同步状态不会合并或写入同步数据。同一空间重新授权后，仅保留此前已开启且此次仍获授权的范围。
- 容量：单份同步历史上限为 32 MiB（Base64 编码后的文档）；交换请求上限 48 MiB，桌面接收上限 96 MiB。单条内容和附件限制保持不变，暂不自动压缩或清理历史。
- 数据副本：关闭同步范围或撤销设备授权只阻止后续同步，不会收回已经复制的数据。凭据与同步对象在两端加密存储，服务端能够解密处理，并非端到端加密。

完整备份用于同端整体恢复和迁机，包含对应实例持久化的 AI 历史；恢复后设备同步需要重新授权。Web 与桌面不能互相恢复完整归档。完全离线的跨端迁移、跨数据库类型迁移及通用 JSON 资源导入导出不属于当前产品能力。


## 统一发布版本入口

继续使用 VS Code 的 Scripts: 版本号更新任务，或 bash scripts/bump-version.sh <x.y.z>。该入口不连接数据库、不执行 SQL、不安装依赖、不构建或运行测试。
脚本仍核对 Web、桌面和打包资产与 VERSION 一致，保留提交、标签、推送的交互确认。发布流水线的 --release 检查使用同一规则。上述操作本轮没有执行。


## 跨端备份适用范围

服务端完整备份可以在本地服务端和 Docker 之间恢复，前提是数据库驱动相同并满足版本要求。桌面完整备份用于桌面端。Web 与桌面端的表结构、账号归属和密钥存储不同，不能直接互相恢复完整归档；一键启用没有改变此限制。跨端个人数据通过远端账户同步，服务器凭据、个人 AI 配置和 AI 历史需单独授权并开启对应范围。完整备份包含对应实例的 AI 历史；跨端流转不会搬运运行中的执行状态。
